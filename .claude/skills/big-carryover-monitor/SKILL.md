# BIG キャリーオーバー監視（造船太郎モニタ）— 手順書

目的: スポーツくじ BIG / MEGA BIG で「1口の期待値がプラス(+EV)になる回」＝2024年第1476回で個人が7,350万円→2.2億円を出したのと同型の「窓」を見逃さず、買い向かうべき回が来たら締切前にアラートする。窓の引き金は「大型キャリーオーバー × 対象試合の中止(台風・荒天)」の掛け算。

この手順書は repo 側が正。スケジュール登録・直近の観測値（比較用の生データ）はマシン側の
scheduled-task ファイルが持つ。戦略の背景は [docs/big-carryover-playbook.md](../../../docs/big-carryover-playbook.md)、
事前登録と照合は [docs/big-carryover-prediction-log.md](../../../docs/big-carryover-prediction-log.md)。

## 鉄則（過去に事故った点）

- **キャリー額は「商品別 繰越金額テーブル」から取る。**ページ冒頭のバナー画像「約○億円 キャリーオーバー発生中」は**古い値で放置される**（2026-07-10 実測: バナー60.1億／実テーブル MEGA 88.3億）。バナーは絶対に使わない。
- **繰越金欄の `-` は 0円ではなく「未確定」**（前開催回が未抽せんの間ずっと `-` 表示）。`-` を見たら直前回の確定繰越を楽天 toto の結果ページ `https://toto.rakuten.co.jp/big/result/<回号>/` で裏取りし「未確定」として扱う。**0 として EV を回してはいけない**（2026-08-01 に約96億を「キャリーなし」と誤報しかけた実例）。
- **繰越が前回観測より減っていたら、直前回の1等口数を楽天結果ページで確認する。**1等が出た正常な減少（例: 第1643回 BIG 1等1口6億円）と、説明できない減少（カナリア）を区別する。
- **中止数 M の認定は toto 公式のお知らせだけ。**気象庁・Jリーグ発表・ニュースは**先行指標**であって判定入力にしない。「延期／振替開催」は試合が成立するので**中止ではない**。M を1つ読み違えると P(1等) が MEGA で4倍・BIG で3倍ずれ、EV判定が壊れる。
- **EVは手計算しない。**リポジトリの calculator を tsx で呼ぶ（下の実行メモ）。プロンプトに式を書き写すと、コード側の改訂に追随せず必ず腐る。

## 手順（毎回・出典URL必須）

1. **現在データ取得**
   - 主ソース: https://store.toto-dream.com/dcs/subos/screen/pi02/spin005/PGSPIN00501InitBIGLotInfo.form
   - ここから、発売中の回号・**商品別の繰越金額**・**商品別の売上金額**・販売締切日時（ネット決済／コンビニ決済）を取る。
   - 補助（締切・日程の裏取り）: https://toto.yahoo.co.jp/schedule/big
   - 締切時刻の構造: **Jリーグ対象回は初戦キックオフの10分前**（土曜の昼〜夕方に来る）。オフシーズン海外回は火曜19:00等。

2. **中止数 M の確認（公式のみ）**
   - https://www.toto-dream.com/information/ の「指定試合の中止について」「第◯回スポーツ振興くじの取扱いについて」を確認。
   - 該当回について**中止が公式に確定した試合数**だけを M に採る。「延期」「振替開催」は M に含めない。告知が無ければ **M=0**。
   - 返還金・不成立の告知は日本スポーツ振興センター(JSC) https://www.jpnsport.go.jp/sinko/ にも出る。
   - **中止カードは必ず指定試合リストと突き合わせる**（楽天 `https://toto.rakuten.co.jp/big/schedule/<回号>/`）。「Jリーグで中止＝Mが増えた」の早合点が過去の事故源（2026-08-07 FC琉球-北九州: 台風中止だが指定外→M=0のまま）。なお **toto の指定13試合は BIG14試合の部分集合**（1644 実測）なので突き合わせは1回でよい。
   - **対象大会を確認する**: 6〜7月のオフシーズン回は海外リーグ（CL予備予選・MLS 等。1638〜1643 で実測）＝日本の台風が無関係で**中止レバーは休眠**。窓が生きるのは**Jリーグ期間の回だけ**。海外回なら「休眠中」と一言で済ませてよい（繰越の積み上がり観測だけ続ける）。

3. **真EVを calculator で算出**（手計算禁止・実行メモのスクリプト方式）
   - `absoluteSalesCeilingForPositiveEv` … 中止数によらない絶対天井 = キャリー ÷ (1−還元率)。**最終売上がこれを超えたら、何試合中止しようが +EV は原理的に存在しない。**まずこれを出す。
   - `calculateBigTrueEv` … 現在の M と、殺到を織り込んだ保守的な想定最終売上での真EV。
   - `minimumCancellationsForPositiveEv` … あと何試合中止すれば窓が開くか。
   - `salesCeilingForPositiveEv` … その中止数での実効売上天井（＝「この売上を超えたら買わない」線）。
   - `classifyBigCarryoverAnticipation` … 殺到度（calm / elevated / flooded）。
   - 想定最終売上は保守側に取る（締切まで日があるほど大きく見積もる。第1476回は通常回の約7倍まで殺到した）。**判定は「想定最終売上を強気に置いても+EVか」で行う。**

4. **台風アウェアネス（先行指標。primed な回がある時だけ実施、平常時はスキップ可）**
   - 気象庁 台風情報 https://www.jma.go.jp/bosai/map.html#contents=typhoon
   - 対象試合の開催日・会場地域に荒天が掛かりそうかを見る。**これは「公式中止告知が出るかもしれない」という先読みであって、EV判定の入力ではない。**
   - 掛かりそうなら再確認タイミングを提示: 台風接近の前日／販売締切の数時間前。

   ★観測可能性ゲート（2026-07-12 調査で確定。最大の実運用リスク）:
   - 規則は「観測して買う」を支持する（中止試合＝全員的中／別試合への振替差し替え制度は無い／個別中止では販売は締切まで継続）。
   - **ただし BIG発売締切は Jリーグ対象時「最初の指定試合キックオフの10分前」に固定**。「買える窓」は**公式の中止確定がこの締切より前に出ている**ことが前提で、規則保証は無い。賭けの operative event は天候でなく**クラブ/主催者の中止決定**（当日持ち越しが多い）。
   - よって: (A)「台風が数日前接近×クラブが締切前に中止を公式公表」＝第1476回型＝**買える窓**。 (B)「荒天濃厚だが締切前に公式中止確定なし／中止対象が締切後の試合」＝**予報賭け**に退化＝観測+EVとして扱わない。
   - 併せて void の崖に注意: M≥5（BIG/MEGA/100円）で不成立＝全額払戻(EV=1.0)。大型台風ほど「当たり」でなく「返金」で終わる。

5. **判定を報告**
   - 「**+EV窓が開いている**（即・買い向かい検討）」… 公式確定した現在の M で真EV≥1、かつ想定最終売上 < 実効売上天井、**かつ その M が販売締切より前に公式確定している**（＝ゲート A）。**締切日時（ネット/コンビニ両方）を明記。**
   - 「primed＋荒天接近（**予報賭け**・要・締切前再確認）」… あと N 試合中止で窓が開くが、締切前に公式中止確定が出るかは不確実（ゲート B）。次に見る日時を明記。
   - 「あと N 試合中止で窓が開く（監視）」／「キャリー不足（窓は遠い）」
   - 平常時は1〜2行で簡潔に（商品別キャリー額＋最小+EV化中止数＋絶対天井）。

6. +EV窓が開いた回は、購入締切に間に合うよう最優先でアラート。

## 回替わり時のモデル検定（翌回キャリー照合）

回号が前回観測から進んでいたら（＝前回の抽せんが終わっていたら）、EV判定の前に**モデル検定**を1回やる:

1. 直前回の確定結果を `https://toto.rakuten.co.jp/big/result/<直前回>/` から取得（確定売上 S・1等当せん口数 W・公表された翌回繰越）。
2. `predictNextCarryoverYen()`（calculator.ts）に S・W・前々回繰越を入れ、**翌回キャリーを円単位で再計算**。
3. lot-info の繰越テーブル実額と**円単位一致**するか照合。一致→「モデル検定 PASS」を1行報告。**不一致→EV判定を出さずに「モデル検定 FAIL（r/α/上限セマンティクスのどれかが腐った）」を最優先で報告**。
4. 事前登録がある回は [docs/big-carryover-prediction-log.md](../../../docs/big-carryover-prediction-log.md) の照合欄も埋める。

真EVは期待値なので単一回で検証できないが、翌回キャリーは S・W から自由パラメータゼロで一意に決まる＝**唯一の毎回検定**。これで α（MEGA0.70/BIG0.80/100円0.76）の腐りを最速検知する。

## カナリア（黙って失敗せず、必ず声を上げる）

次のいずれかに当てはまったら、EV判定を出さずに**「取得失敗」として明示的に報告**する。「不明」のまま平常運転の報告を返すのが最悪の失敗（過去に発生）。

- lot-info ページから回号・繰越金額・売上金額のいずれかがパースできない
- バナーの「約○億円」と商品別テーブルの値が大きく食い違う（→ テーブルを採用し、乖離を報告）
- 同一回号内で売上金額が前回観測より**減っている**（売上は締切まで単調増加するはず）
- 回号が前回観測より**戻っている**
- 締切日時が既に過去
- 回替わり時のモデル検定が FAIL（円単位不一致）

比較用の「前回観測値」はマシン側の scheduled-task ファイルに保持し、毎回そこを更新する。

## 制約・前提

- BIG/MEGA BIG はコンピュータがランダム発券＝買い目選択のエッジは無い。「+EV回に資金を量で入れる」戦略であり買い目予想ではない。過度な煽り（必勝・全力買い等）はしない。
- **+EV ≠ 回収可能。**エッジはほぼ全部1等。少額では「ほぼ確実に負け、ごく稀に大勝」の宝くじ型分布になる。造船太郎の第1476回ですら1等ゼロの確率が約2.4%あった。**購入判断・金額はユーザーが決める。こちらは金額を推奨しない。**
- 中止5試合以上（MEGA: 成立8試合未満／BIG・100円BIG: 成立10試合未満）で**くじ不成立＝全額払戻**。EVは1.0に落ちる。
- **BIG1000・mini BIG は繰越が付かない商品**＝EV上界0.50・+EV窓は原理的に開かない。監視対象外。
- 対象が海外リーグ（CL予選/MLS 等・6〜7月のオフシーズン）の回は**中止レバー休眠**。
- 数値には必ず出典URLを付ける。
- 参考実装: `src/lib/big-carryover/calculator.ts`（真EV・天井・殺到度・翌回キャリー予測）、`src/lib/big-carryover/rules.ts`（公式ルール捕捉）、`src/lib/big-official.ts`（lot-info パーサ）、`src/lib/parimutuel-edge.ts`（控除率の壁・優位比）。

## 実行メモ（無人実行のため承認プロンプトを出さない書き方）

- EV計算スクリプトはリポジトリ内（.tmp 等）に作らず、**セッションのスクラッチパッドに Write ツールで作成**し `npx tsx <絶対パス>` で実行する。calculator はこのリポジトリの `src/lib/big-carryover/calculator.ts` を絶対パスで import する。
- ヒアドキュメント（`cat > file <<EOF`）・`rm -rf`・`sed -i` は使わない。後片付け不要（スクラッチパッドはセッション毎に隔離）。
- 必要な許可（WebFetch 各出典ドメイン／`npx tsx`／`date`／スクラッチパッド Write／scheduled-tasks の list・create・update）は `.claude/settings.local.json` で付与済み。新しい出典ドメインを使う時だけ allow 追加が要る。
