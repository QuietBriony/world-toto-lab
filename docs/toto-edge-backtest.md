## 0. 結論（先に）

| 問い | 答え |
| --- | --- |
| オッズは群衆より正確か | **YES**（logloss 1.0528 vs 1.1059・Brier 0.6340 vs 0.6702、n=650） |
| 群衆に系統的な歪みはあるか | **YES**。引き分けを **約23%過小評価**（ρ=1.232, 95%CI 1.067–1.396, n=568） |
| +EV の券は存在するか | **理論上YES**（61回中61回で最適券EV≥1・中央値3.79） |
| 実弾で回収できるか | **実質NO**。P(1等)=1/48,722。年30回×200口（60万円）でも当たる確率 **11.6%** |
| 次にやるべきことは | 1等狙いではなく **2等・3等のカバレッジ最適化**。J2/J3 のオッズ入手 |

**要するに BIG と同じ病気**: +EV は本物でも分布が宝くじ型で、現実的な予算では回収できない。
ただし「群衆の引き分け過小」は統計的に有意な実在の歪みで、2等・3等狙いには直接効く。

## 2. モデルは群衆より正確か → YES

| 指標（小さいほど良い） | オッズ p_model | 群衆 p_public |
| --- | --- | --- |
| log loss | **1.0528** | 1.1059 |
| Brier | **0.6340** | 0.6702 |

差 0.053 nats/試合 ＝ 尤度比にして **1試合あたり約5.4%** の優位。
13試合の積では 1.054^13 ≈ **1.97** で、必要な壁 2.0 とほぼ同じ水準に届く。

> ★ここで重要な構造: 壁 2.0 は「群衆の2倍正しい」ではなく、
> **13試合の積**なので 1試合あたり **2^(1/13) = 1.055 倍**で足りる。
> 以前「群衆の2倍うまくないと勝てない」と表現したが、券単位の話であって
> 試合単位では 5.5% でよい。この分解を見落とすと難易度を過大評価する。

## 3. 群衆の歪み → 引き分け過小が実在（最重要の実測）

n=568（オッズと結果が揃った試合）:

| | 引き分け確率 |
| --- | --- |
| 群衆 p_public 平均 | 0.2230 |
| オッズ p_model 平均 | 0.2800 |
| **実現（実際の引分率）** | **0.2746 ± 0.0367（95%CI）** |

**ρ = 実現 ÷ 群衆 = 1.232（95%CI 1.067 – 1.396）**

→ 群衆は引き分けを**約23%過小評価**しており、下限でも 1.067 で 1 を上回る＝**統計的に有意**。
オッズは実現値をほぼ正確に当てている（0.280 vs 0.275）。

第1644回の事前登録で立てた「引き分け過小仮説」は、**その回では 0/4 の空振り**だったが、
568試合の母集団では**支持された**。1回のサンプルで仮説を捨てなかった判断が正しかった。

## 4. 券単位のEV → 理論上は +EV、ただし到達不能

### 正しいEV式（払戻の飽和を含む）

素朴に `EV = Π(p_model/p_public) × r` とすると EV 98倍などの異常値が出る。
**払戻はプールと1等上限で飽和する**ため（BIG の1等上限と同じ構造）:

```text
EV = Π p_model_i × min( (r·S + C) / (1 + E[同時当選]) , 上限 ) / 100円
E[同時当選] = (N − 1) × 群衆の組み合わせシェア
群衆シェア = (1−w)·Π p_public_i + w/3^13     ← 第2項＝ランダム/マルチ購入の一様床
```

**群衆シェア ≈ Π p_public_i（積モデル）は実データで検証済み**: 第1644回の実結果に対し
積モデルの予測1等口数 8.8〜10.5口 に対し**実際7口**（一様モデルは0.63口＝10倍外れ）。

### 結果（61回・13試合そろい＆オッズ8試合以上）

| | 通常回（キャリー0） | キャリー3,600万円の回 |
| --- | --- | --- |
| 最適券EV 中央値 | **3.79** | 6.51 |
| EV≥1 だった回 | **61/61（100%）** | 61/61 |
| 最適券の P(1等) 中央値 | **2.05e-05 = 1/48,722** | 同左 |
| 的中時の払戻 中央値 | 2,055万円 | 3,534万円 |

一様床 w の感度: w=0.2→3.35 / 0.5→3.79 / 0.8→5.13 / 0.95→7.59。**仮定に頑健**。

### 到達可能性（これが結論）

| 毎回の投下 | 年30回での1等到達確率 | 年間投下額 |
| --- | --- | --- |
| 1口 | 0.06% | 3,000円 |
| 20口 | 1.2% | 60,000円 |
| 200口 | **11.6%** | 600,000円 |

**EV 3.79 でも、年60万円investして1等を引く確率は約12%**。
+EV と回収可能性は別物という BIG レーンの教訓がそのまま当てはまる。

## 5. この結果を信用しすぎない理由（既知のバイアス）

1. **クロージングオッズの先読み**（最大の弱点）: 使ったのは Pinnacle クロージング。
   toto 締切は初戦KO10分前なので、**2日目の試合のクロージングオッズは購入時点で存在しない**。
   実運用ではオープニング〜締切時点のオッズしか使えず、精度は落ちる。
   → 次の改善: オープニングオッズ列を持つソースで再測。
2. **選択バイアス**: 優位比が最大の出目を選ぶ＝推定ノイズが最大の場所を選ぶことでもある
   （winner's curse）。ただし単試合レベルでは選抜出目の実現的中率 30.8% vs モデル期待 ≈31% で
   **較正は保たれていた**ので、ノイズだけではない。
3. **J1 のみ・平均9.3/13**。残り3.7試合は中立扱い＝保守側だが、**歪みが最も大きいのは
   むしろJ2/J3の可能性**（第1644回で外した3試合中2つがJ2、いずれも群衆が55〜59%支持した
   本命が最下位人気の出目に敗北）。ここが測れていない。
4. 1等的中は 108回の検証で **0回**。EVは稀な大当たりが支配するので、この検証では
   EVの実現値そのものは確認できていない（理論値のみ）。

## 6. 2等・3等カバレッジ最適化（2026-08-10 実装・第2回）

1等狙いをやめて `src/lib/toto-portfolio.ts` を実装し、同じ61回で予算別に測り直した。

| 予算 | EV倍率 | P(1等) | P(2等) | P(3等) | **何かしら当たる** |
| --- | --- | --- | --- | --- | --- |
| 1口（100円） | **1.724** | 0.00% | 0.06% | 0.47% | 0.54% |
| 5口（500円） | 1.493 | 0.02% | 0.27% | 1.57% | 1.86% |
| 20口（2,000円） | 1.141 | 0.08% | 0.88% | 4.07% | **5.03%** |

読み取れること:

1. **EVと的中頻度はトレードオフ**。1口目が最良で、足すほど EV は下がる（1.72→1.14）。
   期待値だけなら集中、体感の当たりやすさなら分散。
2. **20口で「何かしら当たる」が約5%＝20回に1回**。1等狙いの 1/48,722 とは桁が3つ違う。
   実弾の位置づけとして現実的なのはこちら。
3. 的中確率のほぼ全部（5.03%中4.07%）が **3等**。2等は0.88%＝100回強に1回。
4. 20口でも EV は 1 を上回っている（1.141）。ただし §5 の先読みバイアスを含む値なので、
   **1.0 に近い数字は「壁の上にいる」と読まず「測定精度の内側」と読むべき**。

実装上の注意（判明した制約）:

- 貪欲最適化は「予算 × 候補プール × 距離2近傍(339通り)」で、予算50口以上は計算量が跳ねる。
  実運用では候補プールの事前枝刈りか近似評価が要る。
- **実現ベースの採点ができていない**: J2/J3 の試合結果が football-data に無いため、
  61回のいずれも13試合ぶんの結果が揃わない（P(1等)等は理論値のみ）。
  楽天 toto の結果ページから出目を取れば埋まる＝次の小タスク。

## 7. 次の工程

1. ~~2等・3等カバレッジ最適化へ切り替える~~ → **§6 で実装済み**（`src/lib/toto-portfolio.ts`）。
2. **結果データの結合**（次の最小タスク）。楽天 toto 結果ページから確定出目を取れば、

3. **J2/J3 のオッズ入手**（最大の欠損）。歪みの本丸がここにある可能性が高い。
4. **オープニングオッズでの再測**（先読みバイアスの除去）。EVが1.1前後の領域では、
   このバイアスの有無で符号が変わりうるので優先度は高い。
5. 引き分け過小 ρ=1.232 は**すぐ使える**。券構成で 0 を厚めに置く根拠になる（ただし
   「本命が強い試合の真の引分率は平均より低い」ので、一律ではなくオッズで個別に見ること）。
6. 最適化器の高速化（予算50口以上で計算量が跳ねる）。

再現用スクリプトはスクラッチパッド（`parse_vote.py` / `survey.py` / `join_all.py` /
`final.py`）。恒久化する場合は取得部を Pages Function か CLI に移すこと。
