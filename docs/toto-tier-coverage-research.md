# toto等級別カバレッジ：独立モデルの研究用計算

2026-10-28。candidate / research-only / stop-before-merge。
旧 `feat/toto-tier-coverage`（`e25d7f1`）の計算案を最新mainから切り出した。
旧枝は変更せず、UI、DB、共有モデル設定、購入導線、自動実行には接続しない。

## 修正した3点

1. キャリーを等級配分前の共通原資へ足していた点を修正。
   `tierPool[d] = sales * returnRate * tierShares[d] + (d === 0 ? carryover : 0)`。
   [公式totoの説明](https://www.toto-dream.com/toto/how/index.html)では、
   1等原資は売上の35%とキャリーの合計（2026-10-28確認）。
2. 選択結果の確率が0だと全等級を0にしていた点を修正。
   0/1/2外しのベルヌーイ畳み込みを順次更新し、0や1でも除算しない。
3. `tierHitProbability[d]` を「最上位の当たり等級」から
   「当該等級に少なくとも1口当たる確率」へ修正。
   同じ真結果で複数等級に当たるため、3要素を合算してはいけない。
   全等級の和集合は別の `anyTierHitProbability` に返す。

各真結果は一度だけ加算し、重複券は当たる確率を増やさない。
ただし口数、コスト、自分の当せん口数による払戻の希薄化は増える。

## 入力と残る近似

- 13試合、出目は配列index `[0, 1, 2]`（表示出目 `[1, 0, 2]`）。
- 確率は有限・非負・合計1、売上は自分の券代を含む総額と定義。
  不正な値は拒否し、黙って正規化や未知の補完をしない。
- 群衆の同時購入分布と試合結果の独立性を仮定する。相関は未検証。
- 払戻は期待当せん口数を分母へ代入する近似。
  `E[pool / winners]` を求める厳密な確率モデルではなく、丸めや
  中止試合、特殊な配分規則、当せん者不在時の再配分は扱わない。
- 1等上限は明示入力。キャリー額から上限を自動変更しない。
- `optimizeTotoPortfolio` は候補プール内の貪欲選択で、大域最適ではない。
  研究用ガードは候補上限1,000・口数上限100。大きい組合せは高コストで、
  常時実行・ブラウザ自動実行を想定しない。試験は候補6・口数3に限定。

## 再現方法と採用しない主張

```sh
npm test -- src/lib/toto-portfolio.test.ts
```

テストは全て合成データ。0確率、キャリーの等級分離、同時に複数等級へ
当たる例、重複券、上限、空集合、不正入力、探索上限を確認する。
3試合だけが変動し残る10試合が確定したfixtureについて、27通りの真結果と
群衆券を独立に全列挙したoracleと、払戻近似・等級確率・和集合を比較する。

旧実装では新規13テストのうち7件が失敗し、3修正後に13件が通過した。
その後、和集合検証と不正入力の2テストを追加した。実際の試験結果はPRに記録する。
これらは算術・定義の検証であり、実際の予想精度・黒字・購入額の根拠ではない。

旧枝のバックテスト追記や「優位は実在する」とするコメントは取り込まない。
既存 `toto-edge-backtest.md` の歴史的数値をこの計算の検証済み根拠にもしない。
実証には締切前に保存された入力、試合IDの結合検証、全対象の結果、
事前固定した選択規則、out-of-sample評価、実配当との照合が別途必要。
本PRはそのデータ取得・バックテスト・本番採用を承認しない。
