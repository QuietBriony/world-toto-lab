# BIG キャリーオーバー 買い場 Playbook

作成日: 2026-08-07

BIG / MEGA BIG / 100円BIG で「1口の期待値がプラスになる回」を見つけて買い向かうための運用戦略。
2024年第1476回（台風で4試合中止・個人が7,350万円→2.2億円）と同型の窓を、見逃さず・誤検出せず拾うことが目的。

関連: [big-carryover-audit.md](./big-carryover-audit.md)（画面と計算式の監査）/ [big-true-ev-rule-capture.md](./big-true-ev-rule-capture.md)（公式ルールの捕捉状況）

**計算は必ず [`src/lib/big-carryover/calculator.ts`](../src/lib/big-carryover/calculator.ts) を呼ぶこと。**
この文書に式を書き写して手計算すると、コード改訂に追随せず必ず腐る。数値は根拠として載せるが、判定は関数で出す。

---

## 1. エッジの源泉はキャリーではなく「中止」

**最重要。ここを取り違えると全部ずれる。**

1等当せん金には**1口あたりの上限**が掛かる（BIG 6億 / MEGA BIG 12億 / 100円BIG 2億）。
上限が張り付く限り、中止0試合のときの1口真EVは

```text
上限 ÷ 組み合わせ数 ÷ 口単価 + 下位等の床 r(1−α)
```

で頭打ちになり、**キャリー額に一切依存しない**。

| 商品 | M=0 の真EV天井 | キャリー900億でも |
| --- | --- | --- |
| BIG | **0.518** | 0.518 |
| MEGA BIG | **0.388** | 0.388 |
| 100円BIG | **0.538** | 0.538 |

→ `trueEvCeilingWithoutCancellations(productType, returnRate)`

**帰結: 「キャリー◯◯億で過去最高」は買い理由にならない。** 中止による確率ブーストが +EV の 100% の源泉であり、
キャリーは中止が起きたときに payout を上限まで満たすための燃料にすぎない。
中止0の回は、どれだけ積もっていても原理的に買ってはいけない。

（この事実は 2026-08-07 に `calculator.test.ts` が人間側の想定を反証して判明した。
「キャリーが十分大きければ M=0 でも +EV になるはず」という直感は誤り）

## 2. どの商品を買うか

| | BIG | MEGA BIG | 100円BIG |
| --- | --- | --- | --- |
| 予想対象 | 14試合 × 3択 | 12試合 × 4択 | 14試合 × 3択 |
| 組み合わせ | 4,782,969 | 16,777,216 | 4,782,969 |
| 1等上限 | 6億円 | 12億円 | 2億円 |
| 口単価 | 300円 | 300円 | 100円 |
| 1等配分 α | 0.80 | 0.70 | 0.76 |
| 中止1試合あたりの確率ブースト | ×3 | **×4** | ×3 |

### 交点は M=2

**「1等上限が大きい MEGA BIG のほうが夢がある」は中止1試合までは誤り。**
1等確率が 3.51倍（16,777,216 / 4,782,969）悪いのに、上限は 2倍（12億 / 6億）にしかならない。
cap 張り付き域では BIG の1等EVが MEGA の **約1.75倍**。同じ金額を入れたとき 1等を引く確率も BIG が 3.5倍高い。

逆転するのは **M≥2**。BIG は確率が上がりすぎて同時当選で1口払戻が崩れるのに対し、
MEGA は母数が大きいぶん、まだ上限近くを1口で取れる。

| 中止数 | BIG | MEGA BIG | 買うべき |
| --- | --- | --- | --- |
| M=0 | 0.518 | 0.388 | （買わない） |
| M=1 | 1.305 | 1.104 | **BIG** |
| M=2 | 1.380 | 2.734 | **MEGA BIG** |
| M=3 | 1.407 | 2.884 | **MEGA BIG** |

→ `rankBigProductsByTrueEv(candidates, { cancelledMatches, returnRate })`
→ `bigProductCrossoverCancellations({ incumbent, challenger, returnRate })`

**交点はキャリー・想定売上で動く。毎回関数で解くこと。上の表は第1644回時点のスナップショット。**

### 100円BIG は原則買わない

絶対天井（= キャリー ÷ (1−還元率)）が低く、**中止が公表されて殺到した時点で +EV が消える**。
第1644回ではキャリー12.84億に対し絶対天井が25.69億しかなく、M=1 でも殺到後は 0.96 まで潰れた。
窓が開いても +EV にならない唯一の商品になりうる。

## 3. 観測可能性ゲート（そもそも買えるのか）

規則上「中止を観測してから買う」は成立する（中止試合＝全マーク的中／別試合への振替差し替え制度は無い／個別中止では販売は締切まで継続）。
**ただし発売締切は Jリーグ対象時「最初の指定試合キックオフの10分前」に固定**で、規則保証は無い。
賭けの operative event は天候ではなく**クラブ/主催者の中止決定**であり、これは当日持ち越しが多い。

- **ゲートA（買える窓）** … 中止が**締切より前に公式確定**している。第1476回型。
- **ゲートB（予報賭け）** … 荒天濃厚だが締切前に確定しない／中止対象が締切後の試合。**観測+EVとして扱わない。**

### 対象試合は「1開催節＝数日」しかない

BIG は1開催節分が対象（典型は土日の2日間。第1644回は 8/8 に10試合・8/9 に4試合）で、複数週にまたがらない。
**台風がその週末に、対象会場のある地域へ、締切前に刺さる必要がある**という三重の条件になり、窓は構造的に狭い。
「1週間あればどこかに当たる」は成立しない。ここがこのレーンの本質的な律速。

会場分布も毎回見ること。第1644回は14会場のうち関西以西が3つ（広島・福岡・長崎）だけ、
札幌はドームで天候中止が原理的に起きなかった。**露出会場を数えないと中止確率を過大評価する。**

## 4. 中止未確定のまま買う場合の損益分岐

券の価値は**購入時点の M ではなく最終的な M** で決まる（買った後に中止が決まっても効く）。
よって中止未確定のまま買う行為は P(中止) への賭けであり、EV は M の分布での混合になる。

```text
EV = (1 − p)·EV(M=0, 平常売上) + p·EV(M≥1, 中止パスの売上)
```

これを 1 と置いて解いた p が「この回を買ってよい最低の中止確率」。

→ `breakevenCancellationProbability({ withoutCancellation, withCancellation, returnRate })`

### 中止パスの売上は「公表タイミング」で変わる

- **締切前に公表されうる回**（露出試合のKOが締切前後にある）… 群衆も観測して殺到する（第1476回は通常回の約7倍）。
  中止分岐は**殺到売上**＝希薄化したEVで計算する。第1644回 BIG の損益分岐: **約61%**。
- **露出試合のKOが締切より後**＝中止決定も締切後になる公算が大きい回 … 誰も織り込めないまま販売が終わる。
  中止分岐は**平常売上のまま＝希薄化なし**で計算する。同: **約58%**。

観測できる窓（ゲートA）は必ず殺到も連れてくる。ゲートBは情報で劣るぶん、価格（希薄化なし）では勝る。
どちらのパスかは露出会場のKO時刻×締切で毎回仕分けてから、`withCancellation` に渡す売上を選ぶ。

第1644回の実測（殺到パス）: BIG **約61%**、MEGA BIG 51〜86%、100円BIG **100%超（＝どんな確率でも分岐しない）**。
現実の中止確率がこれを下回るなら、純EV上の正解は「買わない」。

## 5. 中止は何で起きるか（実務）

Jリーグの中止判断はホームクラブが「観客・選手の安全確保」で下す。引き金は:

- **暴風警報**が試合時間帯にかかる予想 ← 圧倒的多数
- 特別警報、公共交通の計画運休
- ピッチ冠水で競技不能

**大雨警報だけではまず中止にならない。豪雨・落雷は「中止」ではなく「中断」扱いが原則。**
「本州に雨が降るから中止が増える」という期待は持てない。

なお中止・延期試合は、**当せん決定日までに行われなければ**全マーク的中扱いになる。
「代替日が決まった＝延期」でも、その代替日が当せん決定日より後なら M に数える。

### M の認定は公式のみ

気象庁・報道・SNS は**先行指標**であって判定入力にしてはいけない。
根拠になるのは **Jリーグ/クラブの正式な中止発表**と [toto公式お知らせ](https://www.toto-dream.com/information/)。
M を1つ読み違えると P(1等) が MEGA で4倍・BIG で3倍ずれ、EV判定が壊れる。

## 6. 不成立の崖

中止5試合以上（MEGA BIG: 成立8試合未満／BIG・100円BIG: 成立10試合未満）で**くじ不成立＝全額払戻**。
EVは 1.0 に落ちる。**引き金の台風が大きすぎると自滅する。**
→ `bigVoidCancelThreshold(productType)`

狙い目は M = 1〜4。

## 7. 売上天井（買ってはいけない線）

パリミュチュエルの不変式 `EV ≤ 還元率 + キャリー ÷ 最終売上` より、+EV の必要条件は

```text
最終売上 < キャリー ÷ (1 − 還元率)
```

**中止が何試合起きても、この売上を超えた回は買ってはいけない。**
→ `absoluteSalesCeilingForPositiveEv` （中止数によらない絶対天井）
→ `salesCeilingForPositiveEv` （中止数を固定した実効天井）
→ `classifyBigCarryoverAnticipation` （殺到度 calm / elevated / flooded）

買い場は殺到しきる前。低売上のまま中止が確定した瞬間が最も濃い。

## 8. データ取得の罠（カナリア）

**黙って失敗せず、必ず声を上げること。「不明」のまま平常運転の報告を返すのが最悪の失敗。**

- **バナー画像の「約○億円 キャリーオーバー発生中」は使わない。** 古い値で放置される
  （2026-08-07 時点でバナー60.1億／実テーブル MEGA 97.49億）。必ず**商品別の繰越金額テーブル**を採る。
- **繰越金の `"-"` は「未確定」であって「ゼロ」ではない。** 前回が未抽せんの間は `"-"` が出る。
  `src/lib/big-official.ts` の `parseYenAmount` は `"-"` を 0 に潰すため、そのまま使うと
  「キャリーなしの平時回」と誤報する。`"-"` を見たら [楽天toto の結果ページ](https://toto.rakuten.co.jp/big/result/) で直前回の確定繰越を裏取りする。
- **繰越が前回観測より減っていたら、直前回の1等口数を確認する。** 1等が出れば減るのは正常
  （第1643回で BIG に1等1口・6億円が出て 49.5億→46.0億）。**説明できない減少はカナリア。**
- 同一回号内で売上が減っている／回号が戻っている／締切が既に過去 → 取得失敗として報告する。

## 9. 判定の出し方

1. `absoluteSalesCeilingForPositiveEv` … まず絶対天井を出す
2. `minimumCancellationsForPositiveEv` … あと何試合中止で窓が開くか
3. `calculateBigTrueEv` … 現在の M と保守側の想定最終売上で真EV
4. `salesCeilingForPositiveEv` … その中止数での実効売上天井
5. `rankBigProductsByTrueEv` … その中止数でどの商品を買うか
6. `classifyBigCarryoverAnticipation` … 殺到度

報告区分:

- **+EV窓が開いている** … 公式確定した M で真EV≥1、想定最終売上 < 実効天井、**かつ その M が締切より前に公式確定**（ゲートA）。締切日時を明記。
- **primed＋荒天接近（予報賭け）** … あと N 試合で窓が開くが締切前確定が不確実（ゲートB）。次に見る日時を明記。
- **あと N 試合中止で窓が開く（監視）** / **キャリー不足（窓は遠い）**

**買うなら締切直前に買う。** 中止発表を見てから買えるのに前倒しで買う理由がない。無料のオプションを捨てないこと。
コンビニ決済はネット決済より締切が早い（第1644回は 12:45 vs 14:35）ぶん情報が減る。

## 11. やらないこと

- **買い目予想はしない。** BIG系はコンピュータがランダム発券なので、選択のエッジは原理的に存在しない。
  これは「+EV回に資金を量で入れる」戦略。
- **金額を推奨しない。** 購入判断・金額はユーザーが決める。
- **+EV ≠ 回収可能。** エッジはほぼ全部1等に載っている（BIG は M=1 でも 1/1,594,323）。
  BIG は1等を外すと戻りが約10%（下位等の床 r(1−α) = 0.5 × 0.20）。
  少額では「ほぼ確実に9割を失い、ごく稀に大勝」の宝くじ型分布になる。EVが1を超えたことと勝てることは別物。
- 「必勝」「全力買い」等の煽り表現を UI・報告に入れない（`calculator.test.ts` が文言を固定している）。
- 数値には必ず出典URLを付ける。
